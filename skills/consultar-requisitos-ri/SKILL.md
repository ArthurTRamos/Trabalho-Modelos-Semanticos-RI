# Consultar requisitos do trabalho

Use esta skill quando o pedido envolver implementar, revisar ou planejar uma parte do Trabalho Prático 2 de Recuperação da Informação.

## Procedimento

1. Localize `Trabalho_Pratico_2_RI_2026.md` na raiz do projeto e consulte `Notas_Projeto_RI.md` para entender o estado registrado. Use o Markdown como especificação primária e pesquise diretamente seu texto; não é necessário extrair conteúdo do PDF correspondente.
2. Pesquise os trechos relacionados ao pedido do usuário e leia contexto suficiente ao redor deles. Não trate resultados isolados de busca como especificação completa.
3. Converta o texto do Markdown em requisitos verificáveis e relacione cada requisito ao escopo do pedido atual. Separe claramente:
   - requisitos explícitos do Markdown;
   - decisões de implementação deixadas em aberto;
   - recomendações ou inferências suas.
4. Inspecione os arquivos relevantes do projeto para entender o estado atual. As notas em Markdown são contexto/histórico, não prova da implementação atual; confirme no código quando isso for importante.
5. Prossiga com a tarefa solicitada respeitando esses requisitos. Preserve o escopo pedido pelo usuário e não implemente etapas não relacionadas apenas porque também aparecem no enunciado.
6. Ao responder, resuma os requisitos determinantes e aponte qualquer ambiguidade ou conflito entre o pedido e o Markdown. Cite o item ou título da seção.

## Limites

- `Trabalho_Pratico_2_RI_2026.md` é a fonte primária para os requisitos da disciplina; as notas do projeto são contexto sobre decisões e estado, não substituem o enunciado.
- Não invente critérios ausentes nem apresente escolhas metodológicas como exigências do professor.
- Se o Markdown não existir ou não puder ser lido, informe a limitação e continue apenas com trabalho que não dependa de adivinhar seus requisitos.
