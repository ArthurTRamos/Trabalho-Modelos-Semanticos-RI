# Registrar notas do projeto

Use esta skill ao concluir uma tarefa que altere ou esclareça implementação, metodologia, experimentos ou decisões do Trabalho Prático 2.

## Procedimento

1. Leia `Notas_Projeto_RI.md` antes de editá-lo para preservar a organização, o idioma e o histórico existentes. O log usa uma seção por etapa e os campos: estado, objetivo, implementação, decisões e justificativas, verificação e resultados, pendências.
2. Revise o diff e os artefatos pertinentes para registrar somente o que foi realmente alterado ou verificado nesta execução. Não trate intenção ou código não executado como resultado observado.
3. Atualize a seção da etapa existente quando o novo fato pertencer a ela; acrescente uma etapa com os mesmos campos se surgir uma etapa nova. Para decisões transversais ou histórico de uma execução sem etapa própria, acrescente uma seção curta de registro datado. Use a data local do ambiente do usuário quando disponível.
4. Para cada decisão relevante, anote a decisão, sua justificativa e, quando pertinente, alternativas consideradas ou requisitos do PDF que a motivaram. Distinga decisões tomadas de opções ainda em aberto.
5. Registre resultados experimentais apenas se foram efetivamente medidos; informe partição, configuração e condições necessárias para interpretá-los. Marque explicitamente experimentos não executados como pendentes.
6. Atualize o estado das próximas etapas e limitações afetadas pela mudança. Evite duplicar conteúdo ou reescrever notas não relacionadas.
7. Confira a edição para preservar o texto anterior pertinente, manter consistência entre as notas e o estado real do projeto e garantir que títulos, tabelas e blocos de código estejam em Markdown válido.

## Limites

- Não fabrique justificativas, métricas, tempos, rankings, validações ou status de execução.
- Não registre segredos, credenciais ou dados pessoais desnecessários.
- A skill orienta o registro após a tarefa; não amplia o escopo da implementação solicitada.
